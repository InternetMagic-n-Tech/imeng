# Moving an imeng from 1.2 to 1.3

No format migration is needed for saved sessions: `schema_version` stays 1 and stored sessions load as they are. Everything new is optional and off by default. What does need your attention is the naming, the database (if you use one), and a few environment variables.

## Names that changed
- The folder is `imengs/` (it was `examples/`, then `apps/`). `IMENG_PATH` (older: `GAME_DIR`) points at one imeng folder; `IMENGS_ROOT` at the folder holding them all. Compose: `PROXY_GAME_DIR` follows the same rename.
- The settings file is `config.json` (or `config.mjs` / `config.ts`). Precedence: `config.mjs`, `config.ts`, `config.json`. The old `imeng.*` and `game.*` names are no longer read (rename the file). Helper code the engine loads (`validate`, `evict`, `phases.hook`) moved into each imeng's `hooks/` folder: set the value to `hooks/validate.mjs` etc. The Discord bridge, `db:migrate --all` and `live` read `config.mjs`/`config.ts`/`config.json` directly.
- The first message that launches an imeng is `Imeng: <name>` (it was `Game:` and then `App:`). Change the first line of `SYSTEM_PROMPT.md` and the cases in `HOW_TO_TEST.md` to match.
- The state branch the narrator reads is `imeng` (`imeng.phase`, `imeng.turn`). The old `game.` form is accepted everywhere in settings (allowed_values, limits, phases, conditions, pii) and in ops, and is rewritten on load. Saved sessions still store the branch as `game`, so nothing in them changes. The shipped imengs use `imeng.`. A prompt that says `game.phase` keeps working, but say `imeng.` in new text so the narrator learns one name.
- Schema file: `imeng-schemas/imeng.schema-v.1.3.0.json`; point `$schema` at it. Regenerate it with `npm run schema` after changing the settings types.

## New in config.json (all optional)
Owner and privacy: `owner` (now also `ask_after`), `telemetry`, `eligibility`, `rehydrate`, `pii`, `pii_mask`, `pii_filter` (names, relations, animals; new classes found by a small judge), `state`, `evict`.
Flow: `crossings`, `phases` loops (a phase may list an earlier one in `next`), `turn_events`, `random_events`, `show_clock`, `write_once`, `question`.
Characters and cards: `dating`, `naming`, `voices`, `deck` (with `hand`), `ruling` (with `suits`, `class_suits`, `table`), `validate` (a JS file that checks every op).
Tables: `ban` (a temporary ban), `credit` (re-entry codes, lending, banking; see docs/IMENG-MAKING.md).

## Database (only with `DATABASE_URL`)
Migrations run in order and the server refuses to start on a stamp it does not know: `001_players`, `002_rehydrate_eligibility`, `003_attachments`, `004_bans_and_pii_tokens`, `005_candidates`, `006_credit`. Run `npm run db:migrate` (`--status` exits 1 when behind). Record the last one in your `HOW_TO_TEST.md`. Tables hold hashes, ids and numbers only: no narration, no real names, and `pii_tokens` and `reentry_codes` keep only hashes. The `cleanup` service removes rows past `expires_at`.

## Environment
Added: `DATABASE_URL`, `STATE_PROBE_MS`, `STATE_EXIT`, `CLEANUP_EVERY_MS`, `PII_SALT`, `TELEMETRY`, `BUCKET_*` (the `cleanup` service needs them too), `DISCORD_JOINS_FILE`, `ATTACH_CACHE_DIR`. `PROXY_API_KEY` now also guards `/admin/evict` and `/admin/credit`, which refuse to run without it.

## Endpoints
New: `POST /admin/evict {prefixes: [...]}` (the Discord bridge calls it when the bot is removed from a channel) and `POST /admin/credit {paid_code}` or `{user_id, credit}` (the payment service).

## Behaviour you may notice
- The Discord bridge never reads messages from before it joined a channel. After being added, the first message it sees must be the launch word, or it stays quiet there until it is removed and added again.
- `/successor`, `/claim`, `/keep`, `/handover`, `/owner`, `/telemetry`, `/reentry`, `/lend`, `/credit`, `/bank`, `/unbank`, `/newcode` exist only when the imeng turns the matching block on.

## Added since the first 1.3 cut
1.3 is the public release. These changes were first written as separate steps and are folded in here; nothing below needs a new version or a format migration (`schema_version` stays 1, saved sessions load as they are, everything is optional and off by default).
- **Renamed `sex` to `gender`** in `seating`: `sexes` is now `genders`, `fields.sex` is `fields.gender`, the text key `sex` is `gender` (`{sex}` is `{gender}`), the actor field defaults to `gender`, and `/seat <age> <gender> [sexuality]`. `sexuality`, `sexualities` and `default_sexuality` are unchanged.

- **`.env` loading:** the npm scripts no longer pass `--env-file-if-exists=.env`; each entry (`server`, `judge-host`, `discord-bridge`, `db-migrate`, `db-cleanup`, `doctor`, `driver`, `sessions`) loads `.env` itself with `dotenv` + `dotenv-expand` (`src/utils/load-env.ts`), so `$VAR` / `${VAR}` expand and shell variables win. A command-line `--env-file*` flag turns the loader off.
- **Compose ports:** the imeng services (`imeng-<game>`, profile `<game>`) use 3002 (`PORT_DUNGEON`), 3003 (`PORT_LIGHTHOUSE`) and 3006 (`PORT_BACKROOMS`); the plain `proxy` service publishes one port, `PROXY_PORT` (default 3008).
- **Game picture:** optional `icon` in imeng.json (a file in the game folder), served at `/icons/<model_id>` and logged at start; backrooms sets `The_Backrooms.jpg`. Open WebUI still needs the file uploaded once in Workspace > Models (its editor takes no address).
- **Hub:** `npm run hub` (`hub.ts`, `src/hub/`) serves every game under `imengs/` on one port, each in its own hidden process. Optional; nothing changes for a game. Settings: `HUB_SKIP`, `HUB_CHILD_TIMEOUT_MS` (docs/OPERATIONS.md).

### Step "1.3 to 1.4"
#### New in config.json (all optional)
- **Card-game mechanics:** `deal: "server"`, `shuffle`, `audit`, `betting: "server"` (side pots, blinds, ante and raise cap read from `game.*`), `blinds: {steps, every}` (casino-style rising blinds), `tips` (a house tip jar). See docs/IMENG-MAKING.md.
- **Tables:** `multiplayer.private.forget` (private notes leave the transcript after their round), `multiplayer.default_after.real_from` (the shot clock follows a game field), `actor_defaults_from` (a table-agreed stack reaches later joiners), `credit.reset`, `credit.start_from`, `credit.currency`, `credit.require_terms`, `credit.max_credit`.
- **Any game:** `derive` (a game field that follows another, server-written), `world` (era, time travel, canon file, anachronisms), `dating.finale` (the finale result text).
- **`limits` now also bound the game's own numbers:** a limit named `imeng.<field>` clamps it like an actor field. A path written `game.imeng.<field>` is read as `game.<field>`.
- **Phase `writers` accept `game.<field>`** keys (lock a setting while a hand is played). Server-owned paths added: `game.contrib`, `pots`, `hands_played`, `blind_level`, `blind_base`, `tips`, `tip_idle`, `tip_mark`, `tip_notice`, `reset_start`.

#### Commands
Only when the matching block is on: `/shuffle`, `/audit`, `/check`, `/call`, `/raise`, `/fold`, `/allin`, `/deal`, `/tip`, `/seat`.

#### Database (`DATABASE_URL`)
New migrations: `007_hand_log` (an append-only copy of each hand's deal, bets, tips and registered settings, 30 days, trimmed on rollback) and `008_code_terms` (the price and currency a re-entry code was issued under). Run `npm run db:migrate`; the server refuses to start on a stamp it does not know. A game with `deal` or `betting` `"server"` refuses to start without `DATABASE_URL`, and the doctor fails it.
`POST /admin/credit` is the entry point for a payment service, which is **hypothetical** here (play chips, no provider, no real money); whatever you wire in is held to the amount and the currency of the code. It now refuses (409) a payment whose amount or currency differs from the code's, or a credit that is not a whole number up to `credit.max_credit`.

#### Behaviour you may notice
- The off-phase hush no longer applies to the first message (the one that launches the game).
- A private answer from the narrator no longer sees other players' private cards (`private_hands.field`).
- Money and codes are private: `/credit`, `/bank`, `/unbank`, `/reentry`, `/newcode` and `/lend` are refused at a shared table (the player is pointed at their private chat), and a re-entry code or a tip offer is told only in the person's private chat (a solo chat is private already);
- A person's private offers are told in their private chat, not in a reply at the table; sessions now keep announcements, credit flags, the cards' audit log, peeks and the hand-log id across a restart.

### Step "1.4 to 1.5"
#### New in config.json (optional, off by default)
- `world.languages: {list, field}`: the tongues that exist; an actor's `field` (default `languages`) lists those they understand. The narrator is told speech in another tongue is heard as sounds. Add the field to `actor_template` and `writable_fields` (the doctor checks). Narrator instruction only; code does not check who understands what.
- `world.universe: {name, jump}`: the universe of the story; `jump` is `none` (default) or `allowed`.

- **Server betting:** a player who leaves mid-hand is now handled in code by `game.leave_rule` (`fold` default, or `split`: stays in for what they bet); `game.npc_aggression` (0 to 1, default 0 = the old fixed NPC rule) lets NPCs raise and bluff from their hand and the table's raise history. Server-owned: `game.npc_stats`, `game.last_raiser`, `game.leavers`.
- **`forfeit`:** `{chance, if, rounds, text, done, missed, penalty}`: the server deals one real player a forfeit (send a picture within some rounds, or take a penalty). Server-owned: `game.forfeit`. The doctor warns when it is set without `DATABASE_URL`.
- **`knowledge.overhear`** and **`producer.nudge`** (`/nudge <text>`): see docs/IMENG-MAKING.md "Overhearing and the producer's nudge". Server-owned: `room.overheard`, `session.nudges`.
- **`sense`** (server betting): every play is weighed against the odds; caught bluffs are seen at showdowns; the narrator gets a read and NPCs weigh it. See docs/IMENG-MAKING.md "Player intelligence". Server-owned: `game.sense`, `game.seen`, `game.weak_raisers`, `game.strong_raisers`.
- **`knowledge.debrief`**: the producer's "what did you gather?" beat at listed phases. Server-owned: `room.debrief`.
- **`knowledge.overhear`** now gives listeners a fragment (some of the words), not the whole fact, and real players at the table are listeners too (told privately, `overhear.text`).
- **Attraction** (`dating`) now runs -1 to 3: a quoted dislike at 0 now goes to -1 (it used to stay at 0), and any quoted warmth takes -1 or 0 straight to 1. The dating judge is also shown what contestants overheard. Saved games load unchanged.
- **`knowledge.covert_with`** (`judge` default): the covert call now goes to the judge model, not the narrator model. Set `main` to keep the old behaviour.

### Step "1.5 to 1.6"
#### New in config.json (optional, off by default)
- `images.safety: {threshold, labels, uploads, renders}`: the image censor (the vision module's Python worker, no network) run on pictures people attach (`/portrait <name>` + picture, or a fetched reference URL) and on every render. A flagged picture is refused (`images.texts.unsafe`) and never stored or sent; a detector that cannot run refuses too (`safety_down`). `threshold` default 0.5; `labels` default the `*_EXPOSED` breast, genitalia, buttocks and anus labels. Probabilistic, not a guarantee.
- Needs the **vision module** (top-level `vision` block; `src/tools/vision/README.md`): a host Python venv with `pip install -r src/tools/vision/requirements.txt` and, for seat pictures, a local YOLO-pose weights file. It replaces the ONNX-in-Node detector: set `VISION_VENV` and `VISION_POSE_WEIGHTS`. The doctor fails a game whose worker is not set up.

### Seat pictures and the start
- **`seating.photo`**: a seat waits for one checked picture (safe for work, exactly one person, a face with a nose (and both eyes when `check.eyes` is set, and a censor face box at `check.face_min`) or a body chin to thighs); the people come from the vision module (YOLO-pose) or `check.url` (a local HTTP checker). Shown to the table at the start, deleted after `keep_hours`. **`seating.start`**: `/start` for the owner, and the show starts by itself when the seats are full; sets the server-owned `game.started`. With `seating.photo`, set `VISION_VENV` and `VISION_POSE_WEIGHTS` on the host.

### Terms and the vision module
- **`terms`** (a markdown file per imeng, sent privately once per person when they are seated / join / start a solo game; database table `terms_sent`, migration `009_terms`) and **`vision`** (the host-only Python worker for seat pictures and the image censor; `vision/`, `scripts/vision-check.mjs`; replaces the ONNX-in-Node detectors: `images.safety.model` and `seating.photo.check.model` are gone, `onnxruntime-node` is no longer a dependency). Every shipped imeng has a `terms.md`.

## Moving a game over
1. Rename files and the first line of the prompt as above. 2. Point `$schema` at the 1.3.0 file. 3. `npm run doctor` with `IMENG_PATH` set to your folder. 4. Run its `HOW_TO_TEST.md` cases. 5. Add only the blocks you want.

The shipped imengs are on 1.3.0.
